# Домашняя работа по SQL

Тридцать запросов к учебной базе по Dota 2 в PostgreSQL. Заготовка на каждую
задачу лежит в `queries/`, проверка запускается одной командой.

## В чём смысл

Проверка устроена не сравнением с эталонным ответом, записанным в файл.
Тест выполняет запрос в PostgreSQL, отдельно вычисляет тот же ответ на Python
по исходным таблицам — обычными списками и словарями, без единой строки SQL, —
и сравнивает два результата.

Поэтому совпадение что-то значит: один и тот же вопрос решён двумя разными
способами и дал одно и то же. Чтобы тест прошёл ошибочно, ошибиться пришлось бы
дважды и одинаково.

Расчёт на Python лежит в `oracle/` и открыт: если условие осталось непонятным,
там видно, что именно считается. Задачи 01–06 — в `oracle/g1.py`, 07–12 —
в `g2.py`, и так далее.

## Как выполнять

1. Поднять стенд: `make up`.
2. Открыть очередную заготовку в `queries/`.
3. Разобрать три служебные строки в её шапке.
4. Написать запрос прямо в этом файле, ниже комментариев.
5. Прогнать одну задачу: `make one N=01`.
6. Перейти к следующей.

Заготовка короткая, вот она целиком — `queries/01_melee_strength.sql`:

```sql
-- 01. Герои ближнего боя с основным атрибутом «сила».
-- primary_attr = 'str' и attack_type = 'melee' одновременно.
--
-- Колонки: hero_id, name, legs
-- Порядок: name по возрастанию
-- Строк:   11
```

Первые две строки — условие, дальше три служебные:

- **Колонки** — имена колонок и их порядок в ответе. По ним сверяется
  результат, так что псевдонимы обязательны; регистр не важен.
- **Порядок** — сортировка, заданная условием. Если она задана, строки
  сравниваются по порядку, иначе — как множества.
- **Строк** — сколько строк должно получиться.

Дробные числа сравниваются с округлением до двух знаков.

## Как пользоваться

| команда | что делает |
|---|---|
| `make up` | поднять PostgreSQL и залить схему с данными |
| `make test` | прогнать все тридцать задач |
| `make one N=07` | прогнать одну задачу по номеру |
| `make psql` | интерактивный сеанс psql, покрутить запрос руками |
| `make reset` | пересоздать базу с нуля |
| `make down` | остановить базу |

Первый `make up` заметно дольше: скачивается образ и заливаются данные.
`make down` данные сохраняет, `make reset` стирает их и заливает заново.

Задачи идут по нарастанию сложности, пятью группами по шесть:

| задачи | тема |
|---|---|
| 01–06 | выборка и условия |
| 07–12 | соединения |
| 13–18 | группировка и агрегаты |
| 19–24 | подзапросы и обобщённые табличные выражения |
| 25–30 | оконные функции и рекурсия |

В базе семнадцать таблиц по Dota 2 и около 160 тысяч строк; подробности —
в [`schema/README.md`](schema/README.md).

Сдаются тридцать заполненных файлов из `queries/` и ничего больше.

## Частые трудности

- `make up` падает на подключении к демону — не запущен Docker.
- Запрос работает в `psql`, а тест падает — разошлись имена или порядок
  колонок, их задаёт строка «Колонки».
- Строки те же, а порядок другой — при равных значениях нужен
  дополнительный ключ сортировки, он указан в строке «Порядок».
- Расхождение в последнем знаке у дробных — округлять нужно по `numeric`:
  `round(avg(x)::numeric, 2)`, а не по `double precision`.
